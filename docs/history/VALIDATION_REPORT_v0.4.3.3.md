## 本轮发现并修复的问题

1. **多工作表 Excel 误合并**：旧逻辑会把 transactions、字段字典和数据概况全部拼接，甚至产生重复别名列。现在优先读取 `transactions`，否则寻找首个满足必要字段的工作表。
2. **数据契约未真正阻断导入**：旧监听器会把包含 P1 错误的文件归档，并将部分新记录写入仓库。现在 P0/P1 会阻断网页、命令行和监听导入；P2 仍作为可导入警告。
3. **SQLite 连接未确定关闭**：原生 `sqlite3.Connection` 上下文只负责事务，不负责关闭。现在读写连接均显式关闭，测试中的资源泄漏警告已清除。
4. **本地服务暴露范围过大**：旧 CLI 默认绑定 `0.0.0.0`。现在本地默认绑定 `127.0.0.1`；只有 Docker 明确绑定 `0.0.0.0`。
5. **Docker 数据路径不稳定**：安装包环境下基于 `__file__` 推断项目根目录可能落到 site-packages。现在 Docker 显式指定 `/app` 根目录和绝对数据库路径。
6. **旧式 XLS 依赖缺失**：新增 `xlrd` 依赖。

## 数据仓库说明

演示仓库仍保留 35 条单价为 0 的无效记录，作为数据质量演示样本。它们被标记为 `data_valid=0`、`sale_valid=0`，不会进入销售、利润和客户指标。普通 `insightflow validate` 会报告一项 P1 提示但返回成功；严格模式会返回失败。这不是财务对账错误。
